# PROJECT_BRIEF.md — 변화탐지 검수 플랫폼

> 본 문서는 변화탐지 검수 플랫폼을 신규 구축하기 위한 **마스터 가이드**입니다.  
> Claude design / Claude Code가 이 문서를 단일 진실 원천으로 사용하여 화면을 구현합니다.  
> 충돌 해결 우선순위와 금지 사항을 반드시 먼저 읽고 작업을 시작하세요.

---

## 0. 프로젝트 개요

**무엇을 만드는가**: 항공·위성영상 기반 AI 변화탐지 결과를 **도엽(1:5000) 단위로 검토**하고, 각 변화 객체(폴리곤)에 **오류분류**를 부여하여 품질이 보증된 검수 결과물을 산출하는 웹 플랫폼.

**누가 쓰는가**:
- **품관원 검수자** (1차 사용자): 전국 도엽에 대해 모든 검수 권한 보유. AI 탐지 결과의 정/오 판정, 오류 유형 부여, 누락 객체 신규 추가, 검수 완료 처리.
- **수치도화 수행업체** (2차 사용자): 자신이 수행한 권역의 검수 결과를 수령·확인하고 후속 작업에 반영. 직접 검수는 하지 않음(읽기 위주).

**왜 만드는가**: AI 변화탐지가 도출한 폴리곤을 사람이 도엽 단위로 신뢰할 수 있게 검증해야 국가기본도 갱신에 사용 가능. 현재 검수자가 GIS 툴을 직접 다루며 수작업으로 처리하는 흐름을 통합 웹 플랫폼으로 일원화하여 검수 효율과 일관성을 확보.

**범위**:
- ✅ 검수 인터페이스, 결과 통계 시각화, 결과물 내보내기
- ❌ AI 모델 자체, 데이터 수집·전처리 파이프라인, 사용자 인증·권한 백엔드(프론트엔드 온리)

## 1. 디자인 원칙 (DESIGN_SYSTEM.md 압축)

> 본 절은 A 시스템(SIQMS 실감정사영상 플랫폼)의 디자인 시스템을 검수 플랫폼에 적용한 것입니다.  
> **세부 토큰값(hex, 클래스 예시, 컴포넌트별 공식)은 동봉된 DESIGN_SYSTEM.md를 권위 있는 참고로 사용**합니다.

### 1.1 시각 정체성 (한 문장)

**"정부·공공 SaaS의 한국형 정통 라이트 테마"** — 압도적 slate 회색조 위에 단일 blue-600 액센트, 한글 font-bold 위계, 옅은 카드 깊이감, 데스크톱 워크스테이션 레이아웃. 화려함보다 신뢰감과 업무 효율을 우선.

### 1.2 절대 규칙 (위반 금지)

다음은 화면 어디에도 어겨선 안 되는 디자인 룰입니다.

1. **단일 액센트 컬러**: 액션·선택·진행은 모두 `blue-600` (hover `blue-700`). 보라색·청록색·다른 파란색 톤 금지. semantic 3색은 `emerald` (성공), `red` (오류·삭제), `amber` (경고)만 사용.
2. **font-bold 우위**: `font-semibold(600)`은 거의 사용하지 않음. 강조는 `font-bold(700)`, 본문은 `font-normal(400)`. 두 단계 대비로 위계를 만든다.
3. **본문 14px / 보조 12px**: 16px 본문 사용 금지. 거의 모든 텍스트는 `text-sm` 또는 `text-xs`.
4. **카드 단일 공식**: `bg-white rounded-xl p-5 shadow-sm border border-slate-100 hover:shadow-md transition-shadow`. 카드는 항상 `rounded-xl`, 입력은 `rounded-md`, 버튼은 `rounded-lg`.
5. **모달 단일 공식**: 오버레이는 항상 `fixed inset-0 z-[1000] bg-black/60 backdrop-blur-sm`, 컨테이너는 `bg-white rounded-xl shadow-2xl`, 헤더·푸터는 `bg-slate-50` + `border-slate-200`. 푸터 버튼은 우측 정렬 (취소 → 확인).
6. **상태 배지 시그니처**: `text-[10px] px-1.5 py-0.5 rounded-full font-medium border` + 의미별 3색 일치 (배경 50 / 텍스트 600 / 보더 100).
7. **고정 골격**: 헤더 `h-14` (56px), 모달 헤더 `h-14`, 모달 푸터 `h-16`. 사이드바 폭은 검수 화면에 맞춰 변경 가능하나 일관 유지.
8. **다크모드 사용 금지**: `dark:` 클래스 등장 시 즉시 제거. 라이트 단일 테마.
9. **이모지 사용 금지**: UI 텍스트, 라벨, 메시지 어디에도. 의미 표현은 lucide-react 아이콘으로만.
10. **인터랙션 절제**: `transition-colors`가 기본. 큰 그림자나 글로우, 강한 스케일 변화 금지. Primary 버튼만 `active:scale-95`.

### 1.3 시스템 토큰 요약

전체 토큰값과 컴포넌트별 패턴은 DESIGN_SYSTEM.md 참고. 빠른 참조용 핵심:

- **폰트**: `'Pretendard', -apple-system, BlinkMacSystemFont, system-ui, Roboto, sans-serif` (별도 import는 시스템 또는 CDN으로 처리)
- **색**: slate 50~900, blue 50/600/700, emerald 50/100/600, red 50/200/600, amber 50/200/600
- **아이콘**: lucide-react, 크기 14·16·18·20px만 사용 (텍스트 옆 14, 일반 16, 큰 버튼 20)
- **차트**: recharts. primary `#3b82f6`, success `#10b981`, warning `#f59e0b`, danger `#ef4444`, multi `['#3b82f6','#10b981','#f59e0b','#ef4444','#8b5cf6','#06b6d4']`
- **스크롤바**: 6px 폭, slate-300 thumb (`.custom-scrollbar` 클래스 정의 사용)

### 1.4 변화탐지 도메인을 위한 디자인 보강

DESIGN_SYSTEM.md에 없지만 변화탐지 검수 특성상 추가 필요한 시각 패턴:

- **변화 유형별 색**: AI 탐지 결과 분류는 차트와 폴리곤 색을 일치시킴 — 신축/신설=`#ef4444` (red), 소멸=`#10b981` (emerald), 갱신=`#3b82f6` (blue), 색변화=`#f59e0b` (amber). B 시스템과 동일한 매핑이며, 검수자가 시각적으로 학습하기 쉽도록 유지.
- **오류분류 색**: 정탐(TP)=중립 회색, 오탐(FP)=red 계열, 미탐(FN)=amber 계열, 보류=slate 계열. 오류분류는 폴리곤 보더 또는 작은 마커로 부착해 변화 유형 색과 충돌하지 않게 표현.
- **검수 상태 배지**: 도엽 단위 — 미검수(slate), 진행중(blue), 완료(emerald), 보류(amber). 1.2절의 상태 배지 시그니처를 따라 만들 것.

## 2. 화면 인벤토리 (FEATURE_SPEC.md 매핑)

> 본 절은 B 시스템(GeoX CityVision)의 화면 구조를 변화탐지 검수 도메인으로 매핑합니다.  
> 화면별 세부 인터랙션은 동봉된 FEATURE_SPEC.md를 참고하되, **도메인 의미는 본 문서가 우선**입니다.

### 2.1 라우팅 결정

```
/                           → 랜딩 (시스템 소개 + 최근 검수 작업 카드)
/sheets                     → 도엽 목록 + 지도 (검수 작업 진입점)
/sheets/:sheetCode          → 도엽 검수 상세 (핵심 화면)
/datasets                   → 데이터셋 목록 (영상·수치도화 자원, 신규 검수 시작)
```

**B와의 차이**: 
- B의 `/analyses` → 우리는 `/sheets` (도엽이 검수의 1차 단위)
- B의 `/analyses/:id` → 우리는 `/sheets/:sheetCode` (도엽 코드가 ID)
- B의 `/resources` → 우리는 `/datasets` (영상·수치도화 데이터셋)

**HashRouter 채택** (정적 호스팅 호환, B 시스템 동일 패턴).

**갱신 (이정표 5 메인 화면 통합)**: 4개 라우트 중 `/`, `/sheets`, `/datasets` 를 **단일 통합 대시보드** 로 합침. 활성 라우트는 2개.

```
/                           → 통합 대시보드 (aerial-survey-manager 패턴, 단일 진입점)
                              · 좌 320px sidebar: "신규 변화탐지 작업" 버튼 + 도엽 카드 리스트 + 필터
                              · 중앙 상단: 한국 전도 (권역 디졸브 + 도엽 메타 polygon)
                              · 중앙 중간: 4개 통계 카드 (검수 면적·도엽 진행·변경 객체·저장 용량)
                              · 중앙 하단: 4개 차트 (월별 라인·권역 도넛·상태 도넛·월별 바)
                              · 페이지 끝: 데이터셋 자원 섹션 (검색 + 업로드 버튼 + 카드 그리드)
                              · 모달: UploadModal + NewTaskWizard
/sheets/:sheetCode          → 도엽 검수 상세 (변화 없음, 시스템 80%)
/sheets                     → / 로 redirect (구 라우트 호환성)
/datasets                   → / 로 redirect (구 라우트 호환성)
```

도엽 카드 클릭 → `/sheets/:sheetCode` 진입.

전역 사이드바·헤더 nav 항목은 모두 제거 (단일 페이지라 불필요). 헤더는 로고 + 알림 placeholder 만.

### 2.2 화면별 매핑

#### 2.2.1 랜딩 페이지 (`/`)

**사용자 목적**: 시스템 진입 후 최근 검수 작업이나 진행 중인 도엽으로 빠르게 복귀, 또는 신규 검수 시작.

**B에서 가져올 것**:
- 히어로 섹션 (좌 카피 + 우 일러스트, CTA 버튼) 구조
- 카드 그리드 (필터 + 정렬 + 진행률 표시)

**도메인 적용**:
- 카드 1건 = 1개 도엽 검수 작업. 카드에 표시할 메타: 도엽코드, 도엽명, 권역, 객체 카테고리(건물/도로) 태그, AI 모델 적용 일자, 검수 상태 배지, 검수 진행률, 기준영상 촬영시점 — 비교영상 촬영시점 (YYYY.MM-YYYY.MM)
- CTA 라벨: "**검수 시작하기**" → `/datasets`로 이동
- 필터: 권역 (수도권북부/수도권남부/강원/충청/전라동부/전라서부/경북/경남), 검수 상태(미검수/진행중/완료/보류), 객체 카테고리(건물/도로), 비교 유형(영상-영상/수치도화-영상)
- 정렬: AI 모델 적용 일자 / 검수 완료 일자 / 도엽코드

**제외할 것**:
- 알림 기능은 백엔드 의존도가 높아 1차 범위에서 제외 (헤더 벨 아이콘은 자리만 두되 기능 미구현)

#### 2.2.2 도엽 목록 + 지도 (`/sheets`)

**사용자 목적**: 검수 대상 도엽들이 어느 권역에 분포하는지 지도에서 파악하면서, 좌측 리스트에서 검색·필터·정렬로 원하는 도엽을 찾아 상세로 이동.

**B에서 가져올 것**:
- 좌 사이드바 + 우 지도 분할 구조
- 검색 / 지도 영역 필터 / 분류 필터 / 정렬 / 클러스터 초기화
- 사이드바 토글 (localStorage 영구화)
- 무한 스크롤 또는 페이지네이션

**도메인 적용**:
- 지도 위 표시: 도엽 격자 오버레이 (1:5000 도엽 인덱스 GeoJSON, EPSG:4326 변환됨), 검수 상태별 색상 칠. 클러스터는 권역 단위로.
- 카드 표시: 도엽코드 (8자리), 도엽명, 권역, 객체 카테고리, 검수 상태, 검수자(품관원 검수자 모드일 때만), AI F1-score (도엽 단위 메트릭이 있으면)
- 필터 추가: 검수자 (자기 담당만 보기 토글, 품관원 검수자 모드 전용)
- 지도 영역 bbox 필터: B와 동일 패턴

**라이브러리 제약 (중요)**:
- B는 OpenLayers, 우리는 **React-Leaflet** 사용. ol 기반 클러스터 라이브러리는 사용 불가. `react-leaflet-cluster` 또는 `leaflet.markercluster` 사용.

#### 2.2.3 도엽 검수 상세 (`/sheets/:sheetCode`) ← **이 시스템의 핵심 화면**

**사용자 목적**: 단일 도엽의 변화탐지 결과를 (a) 두 시점 영상을 비교하면서 검토, (b) 변화 객체 단위로 속성·통계 확인, (c) 신뢰도·지역·카테고리·유형 필터로 좁히고, (d) **각 객체에 오류분류 부여** + 잘못된 객체 편집·삭제 + 누락된 객체 신규 추가, (e) 도엽 검수 완료 처리, (f) 결과 내보내기.

**B에서 가져올 것** (B 시스템의 가장 풍부한 화면, 거의 모든 패턴 차용):
- 좌 사이드바(필터) + 중앙 지도 + 우 슬라이드인 패널의 3분할 구조
- 좌 사이드바 아코디언 6개 영역
- 4종 지도 뷰어 모드 (단일/2분할/X스와이프/Y스와이프)
- 지도 위 떠있는 도구바 (뷰어 모드 / 편집 모드 / 다중선택)
- 객체 인터랙션 3단 흐름 (선택 → 정보 오버레이 → 편집/삭제)
- 우측 슬라이드인 리포트 패널 (탭 + 도넛 + 통계표 + 누적막대 + 상세목록 페이지네이션)
- **단일 진실 원천 필터 동기화**: 좌 사이드바의 모든 필터가 지도 + 카운트 + 우측 패널 모두에 동시 영향

**도메인 적용 — 좌 사이드바 아코디언 변경 사항**:

1. **도엽 정보** (B에는 없는 신규 섹션, 최상단):
   - 도엽코드, 도엽명, 권역, 면적
   - 검수 상태 배지 (미검수/진행중/완료/보류)
   - 검수자 정보 (있을 시)
   - "도엽 검수 완료 처리" 버튼 (모든 객체 처리 완료 시 활성)
   - "검수 보류" 버튼

2. **지역 선택** (B의 시군구/읍면동 → 우리는 도엽 내 행정구역):
   - 1:5000 도엽 1매에 보통 여러 행정구역이 걸침. 도엽 내 시군구·읍면동 옵션만 노출.
   - 동일하게 2단 셀렉트 (시군구 → 읍면동), "전체" 옵션 포함.

3. **분석 데이터** (B와 거의 동일):
   - 기준 데이터 가시성 토글 + 메타 (영상 vs 수치도화, 촬영/제작 시점)
   - 비교 데이터 가시성 토글 + 메타
   - 비교 유형 표시 (영상-영상 / 수치도화-영상)

4. **확신도** (B와 거의 동일):
   - 이중 범위 슬라이더 (0~100), 도움말 툴팁
   - **추가**: 미리 지정된 임계값 토글 ("F1 80%+ 결과만", "고확신만 (90%+)" 등 프리셋 버튼)

5. **변화 카테고리** (B의 건물 변화 / 도로 변화 그대로):
   - **건물 변화** (object category 1): 4개 변화 유형 — 신축, 소멸, 갱신, 색변화
   - **도로 변화** (object category 2): 3개 변화 유형 — 신설, 소멸, 갱신
   - 카테고리 마스터 체크 + 유형별 체크 + 카운트 (확신도·지역 필터 적용된 / 전체)
   - 각 유형 펼치면 객체 미니 표 (위치 아이콘 / ID / 확신도 / 면적 / **오류분류 배지**)

6. **오류분류** (B에는 없는 신규 섹션):
   - 오류분류별 카운트 표시 (TP / FP / FN / 보류)
   - 각 오류분류 토글 → 지도 폴리곤 가시성 필터
   - "**미분류 객체만 보기**" 토글 → 검수자가 빠르게 미처리 객체에 집중

7. **검수 히스토리** (B와 동일):
   - 편집/삭제/추가 이력 표 (위치 / ID / 카테고리 / 변경 내용 / 검수자 / 시각)
   - 행 클릭 → 지도 이동 + 폴리곤 선택. 삭제 이력은 별도 마커로 일정 시간 표시.

**도메인 적용 — 객체 정보 오버레이 변경 사항**:

B의 정보 오버레이 (탐지모델 / ID / 변화유형 / 확신도 / 면적 / 주소 / 의견)에 다음을 추가:

- **오류분류** 필드 (정탐 / 오탐-그림자 / 오탐-식생 / 오탐-차량 / 오탐-기복변위 / 미탐 신규 / 보류)
- **검수자** 필드 (오류분류 부여한 사람)
- **검수 시각** 필드

오버레이 푸터 버튼 변경:
- B: 삭제 / 폴리곤 수정 / 정보 수정
- 우리: **오류분류 부여** (메인 액션, primary 버튼) / 폴리곤 수정 / 삭제 / 의견 작성

"오류분류 부여" 클릭 → 같은 자리에서 편집 카드로 전환:
- 오류분류 select (라디오 또는 드롭다운)
- 의견 textarea (선택, 100자 제한, B와 동일)
- 적용 / 취소

**도메인 적용 — 지도 도구바 변경 사항**:

B와 거의 동일. 단, 라이브러리 제약(React-Leaflet)으로 인한 변경:
- 화면 2분할: `<MapContainer>` 두 개를 좌우로 나란히 배치, view를 동기화 (React-Leaflet `useMap` 활용)
- X/Y 스와이프: `leaflet-side-by-side` 플러그인 사용 또는 직접 구현
- 폴리곤 그리기 / 편집: `react-leaflet-draw` 또는 `leaflet-editable` 사용
- Undo/Redo: 직접 구현 (배열 기반 히스토리 스택)

**도메인 적용 — 우측 리포트 패널 변경 사항**:

B의 탭 구조(건물변화 / 도로변화)는 그대로. 패널 본문에 다음 추가/변경:

- 헤더: "분석 결과" → "**검수 진행 현황**"
- 총 건수 / 총 면적 외에 추가: **검수 완료 건수 / 미검수 건수 / 보류 건수**
- 도넛 차트: 변화 유형 분포(B와 동일) + **두 번째 도넛**: 오류분류 분포 (TP/FP/FN/보류)
- 통계 표 컬럼 변경: 유형 / 검출면적 / 검출건수 / **TP건수 / FP건수 / FN건수 / 미분류건수**
- 누적 막대 차트: 행정구역별 변화 유형 분포 (B 동일)
- "**도엽 메트릭**" 신규 영역: 현재 도엽의 F1-score, Recall, Precision (검수 결과 기반 자동 산출)
- 상세목록 그리드 컬럼 추가: 위치 / ID / 주소 / 면적 / 변화유형 / **오류분류** / **검수자** / **검수시각**
- 상세목록 필터 셀렉트: 변화유형 + **오류분류** (이중 필터)

**도메인 적용 — 푸터 버튼 변경**:
- B: 분석결과 내보내기 / 리포트 보기
- 우리: **검수결과 내보내기 (SHP)** / **검수결과 내보내기 (DXF)** / **리포트 다운로드 (PDF)** / 리포트 패널 보기

#### 2.2.4 데이터셋 목록 (`/datasets`)

**사용자 목적**: 변화탐지에 사용 가능한 영상·수치도화 데이터셋을 탐색하고, 비교 쌍을 선정하여 신규 변화탐지 작업을 등록.

**B에서 가져올 것**:
- 좌 사이드바 + 지도 + 우상단 위저드 패널 구조
- 카테고리 토글 (영상 / 수치도화)
- 무한 스크롤
- 3단계 위저드 (데이터 선택 → 모델 선택 → 메타 입력)
- 두 자원 선택 후 **중첩률 자동 계산** + 중첩 없을 시 알럿
- 카드 클릭 → 지도가 자원 bbox로 이동 + 타일 미리보기

**도메인 적용**:
- 카드 메타: 데이터셋 ID, 종류 (정사영상 / 수치지형도), 플랫폼 (위성/항공/드론), 촬영·제작 일자, 도엽 코드 목록 (해당 데이터셋이 커버하는 도엽들)
- 카테고리 라벨: 영상 → "**정사영상**", 수치지도 → "**수치지형도**" (도메인 정확 용어)
- 위저드 단계는 그대로 3단계지만 라벨 변경:
  1. **자원 선택** (기준 자원 + 비교 자원 — B의 "데이터 선택")
  2. **객체 카테고리 선택** (건물 변화탐지 / 도로 변화탐지 — B의 "분석모델 선택")
  3. **작업명·설명 입력** (B의 "내용 입력")
- 위저드 실행 결과 → "이 작업이 커버하는 도엽 목록" 자동 산출 → 사용자 확인 → 도엽 단위로 작업 생성 (1 작업이 N개 도엽을 포함)
- 위저드 실행 후 confirm 다이얼로그 → "도엽 목록으로 이동하시겠습니까?" → `/sheets`

**제거**: 백엔드가 필요한 실제 분석 실행은 본 프론트엔드 범위 외. 위저드 마지막 단계는 "분석 작업 등록" 의도만 표현하고, 실제 실행은 별도 백엔드 흐름(본 범위 외)에 위임.

## 3. 도메인 데이터 스키마

> 모든 좌표 데이터는 **운영(파일) 좌표계 EPSG:5186 ↔ 프론트 좌표계 EPSG:4326** 변환을 거쳐 사용합니다.  
> 변환은 `proj4js`로 빌드 시 또는 정적 GeoJSON 생성 단계에서 처리하고, 프론트엔드 런타임에서는 EPSG:4326만 다룹니다.

### 3.1 도엽 (MapSheet) — 검수의 1차 단위

```typescript
interface MapSheet {
  code: string;              // 도엽코드 8자리, 예: "37708034"
  name: string;              // 도엽명, 예: "안양"
  region: string;            // 권역, 예: "수도권남부 권역"
  bbox: [number, number, number, number]; // [minLon, minLat, maxLon, maxLat] EPSG:4326
  geometry: GeoJSON.Polygon; // 도엽 경계 폴리곤 EPSG:4326
  area_km2: number;          // 면적
  
  // 검수 상태
  review_status: 'pending' | 'in_progress' | 'completed' | 'on_hold';
  reviewer: string | null;
  reviewed_at: string | null; // ISO 8601
  
  // 작업 메타
  task_id: string;            // 상위 변화탐지 작업 ID
  models: ('building' | 'road')[];
  compare_type: 'image-image' | 'image-digital';
  standard_resource_id: number;
  compare_resource_id: number;
  
  // 메트릭 (검수 결과 기반 자동 산출, 미완료 도엽은 null)
  f1_score: number | null;
  precision: number | null;
  recall: number | null;
  
  // 통계
  total_detections: number;       // AI 탐지 객체 총수
  reviewed_detections: number;    // 오류분류 부여 완료 수
  tp_count: number;
  fp_count: number;
  fn_count: number;
}
```

### 3.2 변화탐지 객체 (DetectionObject) — 검수의 2차 단위 (폴리곤 1건)

```typescript
interface DetectionObject {
  id: string;                       // UUID 또는 SHP FID 기반
  sheet_code: string;               // 소속 도엽코드
  
  // AI 탐지 결과 (불변, 입력)
  model: 'building' | 'road';
  change_type: ChangeType;          // 아래 참고
  confidence: number;               // 0~100, AI 확신도
  area_m2: number;                  // 면적 (㎡)
  geometry: GeoJSON.Polygon;        // 폴리곤 EPSG:4326
  region_code: string;              // 행정구역 코드 (앞 5자리=시군구, 8자리=읍면동)
  address: string;                  // 행정주소 텍스트
  
  // 검수 결과 (가변, 출력)
  error_class: ErrorClass | null;   // 오류분류, null=미검수
  reviewer_memo: string;            // 검수 의견, 100자 제한
  reviewed_by: string | null;       // 검수자
  reviewed_at: string | null;       // ISO 8601
  
  // 메타
  is_user_added: boolean;           // 검수자가 신규 추가한 객체인지
  is_deleted: boolean;              // 검수자가 삭제 처리했는지 (소프트 삭제)
}

type ChangeType =
  // 건물 변화
  | 'building_new'        // 신축
  | 'building_removed'    // 소멸
  | 'building_updated'    // 갱신
  | 'building_color'      // 색변화
  // 도로 변화
  | 'road_new'            // 신설
  | 'road_removed'        // 소멸
  | 'road_updated'        // 갱신
  ;

type ErrorClass =
  | 'TP'                  // 정탐 — AI 결과가 옳음
  | 'FP_shadow'           // 오탐 — 그림자
  | 'FP_vegetation'       // 오탐 — 식생 변화
  | 'FP_vehicle'          // 오탐 — 차량 등 일시 객체
  | 'FP_relief'           // 오탐 — 기복변위
  | 'FP_other'            // 오탐 — 기타
  | 'FN'                  // 미탐 — 검수자가 신규 추가 (AI가 놓침)
  | 'on_hold'             // 보류 — 재검토 필요
  ;
```

## 4. 사용자 시나리오 & 권한 처리

### 4.1 품관원 검수자 (1차 사용자)

전형적 워크플로우:
1. 랜딩에서 진행중 도엽 카드 클릭 → 도엽 검수 상세
2. 좌 사이드바에서 **확신도 슬라이더 = 80~100** 으로 좁힘 (고확신부터 빠르게 처리)
3. 변화 카테고리 마스터 체크 → 폴리곤 노출
4. 객체 클릭 → 영상에서 시각 확인 → 정보 오버레이의 "**오류분류 부여**" 클릭
5. 적절한 오류분류 선택 (정탐/오탐-그림자/...) → 적용
6. 모든 객체 처리 후 "**도엽 검수 완료 처리**" 버튼 클릭 → 확인 다이얼로그 → 완료 상태 전환
7. "**검수결과 내보내기 (SHP)**" 클릭 → 클라이언트 SHP 생성 다운로드

품관원 검수자는 모든 도엽·모든 액션 접근 가능. UI 차등 없음.

### 4.2 수치도화 수행업체 (2차 사용자)

전형적 워크플로우:
1. 랜딩에서 자기 권역의 완료된 도엽 카드 확인
2. 도엽 검수 상세 진입 → **읽기 모드** (편집 도구 비활성)
3. 검수 결과 확인, 오류분류 통계 확인
4. "**검수결과 다운로드**" 클릭 → SHP/DXF 받기

읽기 모드에서 비활성화되는 요소:
- 좌 사이드바 — "도엽 검수 완료 처리", "검수 보류" 버튼 숨김
- 지도 도구바 — 폴리곤 생성, 다중 선택, 폴리곤 이동 도구 숨김 (단일 선택은 유지, 정보 조회용)
- 객체 정보 오버레이 — "오류분류 부여", "삭제", "폴리곤 수정" 버튼 숨김 (정보 조회만)
- 우 패널 — 동일하나 검수 진행률 정보는 표시됨

### 4.3 권한 처리 결정

**프론트엔드 온리 + 백엔드 인증 없음** 전제이므로:

- 1차 구현: **사용자 모드 토글** (헤더 우측 어딘가에 "검수자 / 수행업체" 모드 전환 드롭다운 또는 빌드 시 환경변수). 클라이언트 측 신뢰 가정, 보안 책임 없음.
- 2차 구현 (추후): 백엔드 도입 시 정식 인증·권한 분기.

이 결정은 SIGMS의 기존 패턴(화면 분리)과 일치하며, 백엔드 도입 시점까지 잠정 운영.

## 5. 충돌 해결 우선순위

작업 중 디자인·기능·도메인이 부딪히는 순간이 반드시 옵니다. 다음 규칙으로 해결:

### 5.1 시각 표현 (색·폰트·간격·radius·shadow·레이아웃 골격)
→ **A 시스템(DESIGN_SYSTEM.md)이 절대 우선**

B 시스템에 매력적인 시각 요소가 있어도 가져오지 않습니다. 예시:
- B의 보라/연보라 액센트 → ❌ 사용 금지. blue-600만 사용.
- B의 연한 색 카드 보더 → ❌. `border-slate-100` 단일 패턴 유지.
- B의 그라데이션 히어로 배경 → ❌. slate 단색 또는 단순 패턴만.
- B의 Pretendard 사용 → ✅ 동일 (둘 다 같음, 우연한 일치)

### 5.2 화면 구조·인터랙션·상태 전이 (레이아웃 영역, 액션 흐름, 모드 토글)
→ **B 시스템(FEATURE_SPEC.md)이 절대 우선**

A 시스템에 같은 화면 종류(예: 카드 그리드, 사이드바)가 있어도 B의 패턴을 따릅니다. 예시:
- 사이드바 토글 동작 → A에는 없음, B의 패턴(localStorage 영구화) 따름.
- 4종 지도 뷰어 모드 → A에 없음, B 패턴 그대로 차용 (단, React-Leaflet 제약 고려).
- 위저드 3단계 흐름 → A에 없음, B 그대로.
- 검수자별 도구바 노출 차이 → B의 도구바 구조 위에 권한 차등 적용.

### 5.3 도메인 의미·용어·데이터 스키마·핵심 워크플로우
→ **변화탐지 도메인이 절대 우선** (본 문서 3·4절이 권위)

B의 라벨/필드/플로우가 우리 도메인과 어긋나면 우리 의미를 우선합니다. 예시:
- B의 "분석" → 우리는 "**검수**" 또는 "**변화탐지 작업**".
- B의 "정보 수정" → 우리는 "**오류분류 부여**" (의미가 완전히 다름. B는 데이터 풍부화, 우리는 품질 검증).
- B의 작업 단위 (`/analyses/:id`) → 우리는 도엽 단위 (`/sheets/:sheetCode`). 도엽이 검수의 1차 단위.
- B에 없는 개념 (오류분류, 도엽 검수 상태, 도엽 메트릭 F1/Recall) → 우리 도메인 추가, 좌 사이드바·우 패널에 반드시 포함.

### 5.4 결정 트리 (헷갈릴 때)

```
A에 있고 B에 없으면 → A 따름 (예: 카드 시각 디자인)
B에 있고 A에 없으면 → B 따름 (예: 무한 스크롤, 사이드바 토글, 위저드)
둘 다 있는데 다르면 → 시각이면 A, 기능이면 B
도메인이 추가 요구하면 → 도메인이 양쪽 다 덮어씀
어떤 것에도 답이 없으면 → 본 문서 작성자에게 질문 (추측 금지)
```

## 6. 금지 사항

작업 중 절대 하지 말 것. 위반 시 결과물을 폐기하고 재작업합니다.

### 6.1 도메인 용어 금지

- **B의 도메인 용어를 그대로 사용 금지**. 매핑표를 따르세요.
  
| B 시스템 용어 | 변화탐지 플랫폼 용어 |
|---|---|
| 분석 / 분석하기 | 검수 / 변화탐지 작업 |
| 분석 목록 | 도엽 목록 |
| 분석모델 | 객체 카테고리 |
| 분석 결과 | 검수 진행 현황 |
| 정보 수정 | 오류분류 부여 |
| 분석명 | 작업명 |
| 의견 | 검수 의견 |
| 데이터 (자원 의미) | 데이터셋 / 자원 |
| 영상 (resource_type) | 정사영상 |
| 수치지도 (resource_type) | 수치지형도 |

- **A의 도메인 용어 사용 금지**. A는 정사영상 *생성* 시스템이지 검수 시스템이 아닙니다. "프로젝트 처리", "Build Orthomosaic", "GSD 설정", "EO 데이터" 같은 A 고유 용어가 본 시스템에 등장하면 안 됩니다.

### 6.2 시각 표현 금지

- **B의 보라색/연보라 액센트** 사용 금지.
- **다크 모드 / `dark:` 클래스** 추가 금지.
- **이모지** 사용 금지 (라벨, 메시지, placeholder 어디에도).
- **그라데이션 배경** (단색 변화 외) 금지. 단, 랜딩 히어로의 매우 옅은 단색 그라데이션은 검토 후 허용 가능.
- **font-semibold(600)** 남용 금지. font-bold(700)와 font-normal(400)의 두 단계 대비를 유지.

### 6.3 기능·기술 금지

- **백엔드 API 호출 코드** 작성 금지. 모든 데이터는 정적 GeoJSON / JSON 파일에서 fetch.
- **localStorage 외 영구 저장 가정 금지**. IndexedDB, Cookie 등 사용 금지.
- **OpenLayers** 신규 도입 금지. 지도는 React-Leaflet으로 구현. (B 시스템의 `ol`, `ol-ext` 코드는 참고만 하고 React-Leaflet으로 재작성)
- **Material UI / MUI** 도입 금지. Tailwind만으로 스타일.
- **localStorage / sessionStorage / 브라우저 스토리지 API**: 사이드바 토글 상태 같은 단순 UI 환경 설정 외에는 사용 금지. 검수 결과 같은 도메인 데이터는 `localStorage`에 임시 저장하되, 사용자가 export하지 않으면 사라질 수 있음을 UI에서 명시.

### 6.4 데이터 처리 금지

- **좌표계 혼동 금지**: 데이터 파일은 EPSG:5186, 프론트엔드 처리는 EPSG:4326. 변환 위치를 명확히 (빌드 시 또는 정적 GeoJSON 생성 단계). 런타임 변환 추천하지 않음.
- **느린 동기 작업으로 메인 스레드 차단 금지**: 폴리곤 17,000+ 건 등 큰 데이터 처리 시 청크 분할 또는 인덱싱 필수.
- **O(n²) 공간 연산 금지**: 폴리곤 충돌·인접 검사 등은 cKDTree류 공간 인덱스(JS의 RBush 등) 사용.

### 6.5 응답·문서 작성 시

- **추측으로 결정 사항 채우기 금지**. 본 문서에 답이 없으면 작성자에게 질문하거나 명시적으로 "[가정: ...]" 표기.
- **불필요한 화면 추가 금지**. 본 문서 2.1의 4개 라우트 외에 새 라우트 신설 금지.
- **B 시스템의 코드를 그대로 복붙 금지**. B는 OpenLayers + MUI + 다른 디자인 시스템임. 패턴만 차용하고 처음부터 작성.

## 7. 기술 스택 결정

| 영역 | 선택 | 비고 |
|---|---|---|
| 빌드 / 번들 | **Vite** | B와 동일 |
| 프레임워크 | **React 18** | A·B 공통 |

| 스타일 | **Tailwind CSS 3.4+** | A와 동일 (extend 없이 기본 팔레트 + custom CSS 최소) |
| 라우팅 | **react-router (HashRouter)** | B와 동일, 정적 호스팅 |
| 상태관리 | **Zustand** | B와 동일, 페이지·도메인별 store 분리 |
| 지도 | **React-Leaflet 4.x + Leaflet 1.9** | A와 동일 (B는 OpenLayers, 차용 안 함) |
| 지도 플러그인 | leaflet-side-by-side, react-leaflet-cluster, leaflet-draw | swipe / 클러스터 / 폴리곤 편집 |
| 좌표계 | proj4js (빌드 단계용), 런타임은 EPSG:4326만 | EPSG:5186 ↔ 4326 변환 |
| 표 | **AG Grid Community** | B와 동일 (페이지네이션·정렬 풍부) |
| 차트 | **recharts** | A와 동일 (B는 Chart.js이나 A 일관성 우선) |
| 토스트 | **react-hot-toast** | B와 동일 |
| 다이얼로그 | **Radix UI** (alert-dialog, popover) | B와 동일 |
| 아이콘 | **lucide-react** | A·B 공통 |
| 파일 export | shp-write, dxf-writer 또는 직접 구현 | SHP/DXF 클라이언트 생성 |
| Linter / Formatter | ESLint + Prettier | 일반 |

**결정 사항 보충**:
- 차트 라이브러리는 A의 recharts를 채택. B의 Chart.js는 사용 안 함. 이유: A의 시각 정체성을 유지하기 위함이며, recharts의 React-native 통합이 더 깔끔.
- 지도 라이브러리는 React-Leaflet 고정. B의 4종 뷰어 모드는 React-Leaflet 위에서 재구현해야 함. 가장 큰 작업량 예상 영역.
- 표는 AG Grid 채택. B와 동일. 페이지네이션 / 정렬 / 셀 클릭 핸들러가 풍부해 검수 화면 상세목록에 적합.

## 8. 구현 작업 권고 순서

1. **디자인 토큰·기초 컴포넌트 정착**: Tailwind 설정 + 글로벌 CSS + Button, Card, Input, Modal, Tabs, Badge, Progress, Tooltip 컴포넌트를 DESIGN_SYSTEM.md 기준으로 만든다.
2. **레이아웃 골격**: 헤더(`h-14`) + 사이드바(`w-340px`, 토글) + 콘텐츠 영역의 `h-screen overflow-hidden` 골격. localStorage 토글 동기화. HashRouter 라우트 4개 빈 컴포넌트로 골조.
3. **도엽 인덱스 + 정적 데이터 인프라**: `public/data/` 디렉토리 + 정적 GeoJSON (1:5000 도엽 격자, 권역별 분할 파일). EPSG:5179→4326 변환 스크립트. Zustand store 골조.
4. **`/sheets` 도엽 목록 + 지도**: React-Leaflet 기본 지도 + 도엽 격자 오버레이 + 좌 사이드바 카드 리스트 + 검색·필터·정렬. 클러스터링.
5. **`/sheets/:sheetCode` 도엽 검수 상세 — Phase 1 (시각화)**: 단일 지도 + 좌 사이드바 6개 아코디언 + 단일 진실 원천 필터 store. 폴리곤 레이어 + 변화 유형별 색상. 정보 오버레이(읽기 전용).
6. **`/sheets/:sheetCode` Phase 2 (4종 뷰어 모드)**: 분할 비교 / X·Y 스와이프. React-Leaflet + leaflet-side-by-side. 도구바.
7. **`/sheets/:sheetCode` Phase 3 (편집 인터랙션)**: 객체 오류분류 부여 카드 / 폴리곤 수정 모달 / 폴리곤 신규 생성 / 다중 선택 삭제 / 검수 히스토리. 모든 액션은 Zustand store + localStorage 임시 저장.
8. **우측 슬라이드인 리포트 패널**: 탭 + 도넛 + 오류분류 도넛 + 통계표 + 누적막대 + 상세목록 페이지네이션. AG Grid + recharts.
9. **export 기능**: SHP / DXF / PDF 리포트 클라이언트 생성·다운로드.
10. **`/datasets` 데이터셋 목록 + 위저드**: 무한 스크롤 + 카테고리 토글 + 3단계 위저드 + 중첩률 자동 계산.
11. **`/` 랜딩**: 히어로 + 카드 그리드 + 필터·정렬. 마지막에 만들어도 무방.
12. **권한 모드 토글 + 수행업체 읽기 모드 차등 노출**.
13. **반응형 / 접근성 / 마이크로 인터랙션 다듬기**.

각 Phase는 독립 검증 가능. 검수자가 실제로 사용해보며 피드백을 흡수해 다음 Phase로.
